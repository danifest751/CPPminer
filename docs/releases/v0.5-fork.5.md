# CPPminer v0.5-fork.5 — Intel Arc support

This release adds Intel Arc GPUs to the release builds, with a new ESIMD XMX
scan that mines **5.9x faster** than the previous Intel path on an Arc A380,
and includes the CUDA improvements developed since v0.5-fork.4.

CPPminer is based on [1640675651/CPPminer](https://github.com/1640675651/CPPminer),
the Pearl/Quantus miner by @foolzhz. Development and release builds are maintained
in this fork; upstream submissions are made only when the fork owner chooses them.

## Intel Arc

Use `--backend onednn` (or the `start-herominers-intel` script). Arc A380 at the
full pool size, 131072 x 131072 x 4096, per complete attempt:

| Path | TMAC/s |
|---|---:|
| `--backend opencl --ocl-dot dpas` | 3.20 |
| `--backend onednn`, gemmstone systolic kernels | 16.66 |
| **`--backend onednn`, ESIMD XMX scan (Linux default)** | **18.79** |

A practical XMX ceiling measured on the same card is 26 TMAC/s; the ESIMD scan
uses about 74% of it.

### ESIMD XMX scan

One kernel per panel does the int8 GEMM with `dpasw` (Xe-HPG), the milestone
tile XOR, the 16-word fold, keyed BLAKE3 and the target comparison, all in
registers. The GPU prep writes noisy A and B directly in the DPAS operand
layouts, so every operand is a single block load. There is no tile_xor buffer
and no second jackpot pass.

- **Linux:** `kernels/libcp_esimd.so` and the SYCL runtime it needs are in the
  package. Only the Intel GPU driver (`intel-opencl-icd`) is required; tested
  with compute-runtime 23.43 (Ubuntu 24.04) and 26.31, without oneAPI installed.
- **Windows:** the package has the oneDNN backend with the gemmstone systolic
  kernels. The ESIMD library is not in the Windows package yet.
- The backend picks ESIMD automatically when the library loads and the GPU has
  XMX, and falls back to gemmstone otherwise. `CP_INTEL_GEMM=esimd` or
  `CP_INTEL_GEMM=gemmstone` forces one of them.
- Arc B-series / Lunar Lake (Xe2) use a compiled-in `dpas` variant with
  execution size 16 that has not been run on such hardware yet.

Validation on the A380: the ESIMD prototype matches a CPU reference on every
milestone tile word and every tile digest; 30 mock shares were built and
verified through the Rust proof verifier, including runs without oneAPI and on
the older driver; live HeroMiners shares were accepted. Details:
[ESIMD](https://github.com/danifest751/CPPminer/blob/v0.5-fork.5/docs/intel_esimd.md),
[oneDNN on A380](https://github.com/danifest751/CPPminer/blob/v0.5-fork.5/docs/intel_a380_onednn.md).

### oneDNN / gemmstone

- XeHPG systolic (XMX) kernels are used: the milestone XOR now fires inside
  K unrolls larger than 128, and a crash in the fallback kernel path is fixed.
- The measured-best kernel (8x4 work group, 16x32 unroll, without `af`) is
  preferred over oneDNN's ranking; panels are 1024x1024 hash tiles.
- The separate jackpot kernel keeps its state in registers, and GEMM panel i
  overlaps the jackpot of panel i-1 on an out-of-order queue.

### Matrix prep (OpenCL)

Work-group noise kernels with vector stores and a 16-wide signal generator:
A prep 200 → 96 ms per attempt and per-job noisy B ~200 → ~80 ms on the A380.
The output is byte-identical to the previous kernels; the OpenCL backends use
the same code.

## CUDA

- Several NVIDIA GPUs in one process now scan independent A matrices instead
  of repeating GPU0's work, and proof data is fetched from the winning GPU.
- CMP 50HX (Turing): `.cg` operand loads, a constant-index predicated jackpot
  fold and an earlier milestone callback; complete-attempt throughput
  60.46 → 63.18 TMAC/s (+4.5%) against v0.5-fork.4.
- Opt-in incremental signal-A generation (`CP_CUDA_A_MODE=incremental`).

## Other

- Opt-in OpenCL DPAS path for Intel (`--ocl-dot dpas`) with lane-layout
  self-tests.
- Linux `build.sh` prepares the oneDNN dependencies itself; new CMake option
  `CP_ENABLE_ESIMD`; the Windows CI build includes the oneDNN backend.
- Tools: register-only DPAS ceiling benchmark, device-wide Level Zero metric
  sampler, Intel scan benchmark.
- Pool agent `cppminer/0.5-fork.5`.
