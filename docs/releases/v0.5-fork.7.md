# CPPminer v0.5-fork.7 — Quantus on CUDA

This release adds a **CUDA backend for Quantus** (`--algo quantus --backend cuda`), rewrites
the Quantus OpenCL kernel, and turns on WMMA for Pearl on AMD RDNA4. **Quantus is mined without
a developer fee** in this release; the Pearl fee is unchanged.

CPPminer is based on [1640675651/CPPminer](https://github.com/1640675651/CPPminer),
the Pearl/Quantus miner by @foolzhz. Development and release builds are maintained
in this fork; upstream submissions are made only when the fork owner chooses them.

Start it with:

```
cppminer --algo quantus --backend cuda --devices 0 --pool stratum+tcp://qtc.kryptex.network:7049 --wallet krx... --worker rig1
```

From Russia use `qtc-ru.kryptex.network:7049`. The packages include `start-quantus-kryptex`.

## What changed

### Quantus CUDA backend

- Goldilocks field arithmetic written for the GPU integer pipes: 32-bit wide products, a
  six-operation 128 → 64-bit reduction with the 2^32 − 1 constant in constant memory (as an
  immediate, ptxas emits a quarter-rate `IMAD.HI` on Turing), squaring from three products.
- The linear layers keep their row sums as lazy 96-bit values; the internal rounds feed the
  unreduced sum straight into each diagonal product.
- Nonces walk a line along which, after the first linear layer, only two lanes change, so the
  first full round needs two S-boxes instead of twelve.
- The lazy sums and the squaring use 64-bit add chains on Turing, Ampere and Ada, which lets
  ptxas use 3-input adds and wide multiply-adds with carry-in: −5% SM cycles per hash on an
  RTX 2080 Ti, −4.4% on an RTX 3090. Blackwell keeps the 32-bit chains, which are 10% faster
  there.
- At start-up the kernel is checked against the CPU reference on sampled nonces, and every
  candidate share is hashed again on the CPU before it is submitted.

### Quantus OpenCL kernel

- Kernel variants (multiply and reduction forms, local size) are probed per device; the
  fastest one that passes the CPU self-test is used.
- Carry-free 22-bit limbs in the linear layers (large gain on Intel, where 64-bit integer
  math is emulated), carry chains through `__builtin_addc` on AMD, lane loops unrolled so the
  state stays in registers, and two launches in flight.
- Arc A380: 30 MH/s. Radeon AI PRO R9700: 162 MH/s per GPU (measured before the
  `__builtin_addc` change).

### Pearl on AMD RDNA4

- WMMA (`v_wmma_i32_16x16x16_iu8`) is now the default on gfx12; the operand layout is picked by
  a self-test at start-up. Radeon AI PRO R9700: 88.5 TMAC/s per GPU (SRBMiner 3.7.2: 90).
- The WMMA milestone code no longer indexes private arrays dynamically, which removes most of
  its scratch traffic on RDNA3 and RDNA4.

### Builds

- Windows and Linux packages are built with CUDA 12.9: native code for sm_75, sm_86 and sm_89,
  sm_120 as PTX that the driver compiles.
- Pool agent `cppminer/0.5-fork.7`.
- New start script `start-quantus-kryptex` (`.bat` / `.sh`).
