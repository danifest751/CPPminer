# CPPminer v0.5-fork.9 — TNet (Requant)

This release adds a third algorithm, **TNet v1** for the [Requant](https://github.com/danifest751/requant)
coin (test network), on NVIDIA tensor cores: `--algo tnet`. It mines into the Requant pool or a
`requantd` node and needs no extra libraries: the int8 GEMM is CUTLASS, compiled into the miner.
Pearl and Quantus are unchanged. **TNet has no miner fee** (Requant funds development in its own
consensus rules); **Quantus is still mined without a developer fee**; the Pearl fee is unchanged (1%).

CPPminer is based on [1640675651/CPPminer](https://github.com/1640675651/CPPminer),
the Pearl/Quantus miner by @foolzhz. Development and release builds are maintained
in this fork; upstream submissions are made only when the fork owner chooses them.

## TNet

```sh
# Requant test-network pool: rewards to your key hash, statistics per device (--worker)
cppminer --algo tnet --rpc 193.187.93.29:19340 --payee <64-hex key hash> --worker rig1

# check the GPU first: SHA-256, expansion and the int8 GEMM against the CPU
cppminer --algo tnet --selftest
```

A key hash comes from the Requant wallet (`requant-wallet keygen my.key`). Pool statistics:
http://193.187.93.29:19380/pool. Test coins have no value.

- **GEMM.** Two CUTLASS int8 tensor-core kernels: `mma.m8n8k16` for Turing and `mma.m16n8k32` with
  three `cp.async` stages for Ampere, Ada and Blackwell. At start-up the miner checks the kernel
  against the CPU on random matrices and refuses to mine if neither kernel agrees; if the newer one
  disagrees it uses the Turing kernel. `CP_TNET_GEMM=sm75|sm80` chooses by hand.
- **Network.** Polling the pool and sending shares happen on their own thread, so the GPU never waits
  for a round trip (the first build stalled on every share: an RTX 5070 behind a slow link gave
  0.2 M tickets/s in the pool, now 4.5–5.3). Every winning ticket of a pass is sent, up to 16.
- **Pool statistics.** `--worker NAME` names the device; one address can have many devices.

| GPU | TNet | |
|---|---:|---|
| CMP 50HX (Turing) | **3.61 M tickets/s** | 3.42 with cuBLAS in the previous test builds |
| RTX 5070 (Blackwell) | 4.5–5.3 M tickets/s | with the previous (cuBLAS) build, in the pool |

## What changed

- `--algo tnet` (alias `requant`): `src/tnet/cp_tnet.cu` (expansion, requantization and ticket kernels,
  byte-compatible with the Requant reference), `src/tnet/cp_tnet_gemm.cu` (CUTLASS GEMM), pool mode
  (`--payee`, `--worker`, share/stale/block counts), `--selftest`. Documentation: `docs/tnet.md`.
- Build: `cp_api.h` is included in `cp_qpow_mine.cpp` for every backend.
- Pool agent `cppminer/0.5-fork.9`.

## Checked before release

- CMP 50HX (Linux): TNet `--selftest`, the forced sm80 kernel falls back to sm75, 45 s in the
  Requant pool with every share accepted (the pool recomputes every share's row), CUTLASS vs cuBLAS
  back to back.
- Windows package built in the Windows VM (CUDA 12.9, CPU + CUDA + OpenCL + oneDNN + ESIMD), with the
  smoke test and the redistributable-package validation; `--algo tnet` present (no GPU in the VM).
- Linux package (Ubuntu 24.04, CUDA 12.9): `--algo tnet --selftest` passes from the extracted archive
  on the CMP 50HX; no missing libraries.
- HiveOS package (Ubuntu 20.04, glibc 2.30): simulated HiveOS install, Quantus on Kryptex, shares
  accepted, `h-stats` reports version 0.5-fork.9.
- Pearl and Quantus code is the same as in v0.5-fork.8.
- Not yet measured: the sm80 GEMM on Ampere, Ada and Blackwell against cuBLAS (the start-up check
  guards correctness there).
