# CPPminer v0.5-fork.6 — packed-operand CUDA kernels

This release replaces the CUTLASS tensor-core scan on NVIDIA Turing, Ampere, Ada
and Blackwell GeForce cards with hand-written kernels that read the noisy
matrices in a packed layout. Same hashes, same shares, less memory traffic:
**+8–14% on the RTX 4090, RTX 3090, RTX 5070 and CMP 50HX** at the same power limit.

CPPminer is based on [1640675651/CPPminer](https://github.com/1640675651/CPPminer),
the Pearl/Quantus miner by @foolzhz. Development and release builds are maintained
in this fork; upstream submissions are made only when the fork owner chooses them.

## Upgrading

- Replace the old folder's files with the new package, or unpack it next to the
  old one and copy your start script settings (pool, wallet, worker).
- No new options are needed: the new kernels are selected automatically.
- **RTX 50 series:** the first start compiles the GPU code for your card in the
  driver and can take one to two minutes before the first `attempt timing`
  line appears. Later starts use the driver's cache and begin at once.
- To go back to the previous kernel on any card, set `CP_CUDA_PACKED=0` before
  starting the miner (`set CP_CUDA_PACKED=0` in a .bat file,
  `export CP_CUDA_PACKED=0` on Linux).

## Speed

Full pool problem size (131072 x 131072 x 4096), default settings, power limit
unchanged. TMAC/s is what pools show as TH/s.

| GPU | Power limit | v0.5-fork.5 | v0.5-fork.6 | Live mining with v0.5-fork.6 |
|---|---:|---:|---:|---|
| RTX 4090 | 450 W | 243.8 | **271.0–274.9** | HeroMiners scan 271.0 TMAC/s, 12 of 12 shares accepted |
| RTX 3090 | 350 W | 99.0 | **112.4–113.5** | HeroMiners scan 108–110 TMAC/s, share accepted |
| RTX 5070 | 250 W | 106.6 | **115.3** | HeroMiners scan 116.8 TMAC/s, 4 shares accepted |
| CMP 50HX | 225 W | 62.5 | **68.4–69.5** | +6% accepted shares per second on a local test pool |

How the numbers were taken:

- **RTX 3090:** both versions on the same rented card in one session, 4096 x
  131072 panels as the miner scans them, 20-second runs in forward and reverse
  order. The SM clock rose from ~1320 to ~1515 MHz at the same 350 W, and the
  share of the INT8 tensor peak per clock went from ~89% to ~90%.
- **RTX 4090:** mock mining at full size, 300 attempts each, same rented card
  and session; 2085 → 2340 MHz at 450 W. The `--align-test` check passes on
  sm_89. A kernel-variant sweep confirmed the shipped configuration (256x128,
  4 stages) as the fastest on Ada too.
- **RTX 5070:** mock mining at full size, 120 attempts each, same session;
  2632 → 2752 MHz at 250 W.
- **CMP 50HX:** kernel panels and mock mining; the share-rate check used a
  local pool at low difficulty for 10 minutes per build (0.445 → 0.473 accepted
  shares per second).
- **Other cards** use the same kernels as the measured ones of their
  architecture (Turing, Ampere, Ada, Blackwell GeForce) but were not measured
  with this release.

## What changed

### Packed noisy operands

The GPU prep now writes noisy A and B^T in a packed layout: every 256-row
(A) or 128-row (B^T) block and 32-wide k-tile is one contiguous record. A
threadblock reads each k-tile of its operands as a single contiguous block,
instead of 16 bytes from each of 256 rows that are 4 KB apart.

That pattern was the main loss on every NVIDIA card we profiled. On the RTX
3090 the CUTLASS kernel kept L2 at 70–73% of its peak throughput with ~16
sectors per warp request, and DRAM at 45–89%; the power-limited clock settled
around 1320 MHz. With packed operands and 256x128 threadblocks, L2 falls to
60%, DRAM to 20%, and the clock rises to ~1515 MHz at the same 350 W. On the
CMP 50HX the GEMM part alone went from 67% to 88% of the tensor peak per clock
when only the layout changed.

The layout costs nothing extra: the prep already writes every noisy element,
it only writes them to different addresses. The signal matrices, hashes,
commitments and proofs are unchanged.

### New kernels

- **sm_75 (Turing: RTX 20xx, CMP 30HX–90HX, T4):** `mma.sync.m8n8k16`, 256x128
  threadblock, eight 64x64 warps, k-tile 32 double-buffered in shared memory
  with XOR-swizzled `ldmatrix` (no bank conflicts), operands fetched one tile
  ahead through registers.
- **sm_8x and sm_12x (Ampere, Ada, Blackwell GeForce):** `mma.sync.m16n8k32`,
  256x128 threadblock, eight 64x64 warps, 4-stage `cp.async` ring of
  contiguous blocks.
- Both fold each milestone right after the barrier, so its XOR and shuffle work
  shares a scheduling region with the next tile's tensor instructions, and keep
  the 16-word transcript of every hash tile in shared memory.
- Hash tiles, transcript words and hit coordinates are bit-identical to the
  CUTLASS kernel, so proofs and pool behaviour do not change.

Which kernel runs where:

| GPU | Default | `CP_CUDA_PACKED=0` | `CP_CUDA_PACKED=1` |
|---|---|---|---|
| Turing, sm_75 | packed m8n8k16 | CUTLASS | packed |
| Ampere / Ada, sm_8x | packed m16n8k32 | CUTLASS | packed |
| Blackwell GeForce, sm_12x | packed m16n8k32 | CUTLASS | packed |
| Hopper / datacenter Blackwell, sm_90 / sm_10x | CUTLASS | CUTLASS | packed (not measured yet) |
| Pascal and older | dp4a / SIMT as before | — | — |

The miner prints `packed-operand scan kernel` at start when the new kernel is
active.

### Validation

- Standalone kernels against an independent CPU oracle: every transcript word
  and BLAKE3 digest of 8192 hash tiles (full int8 range, all -128 rows), plus 96
  sampled tiles of a 4096 x 131072 panel; jackpot coordinates checked.
- `--align-test` now also checks the packed kernel on packed copies of real
  Pearl noisy matrices against the CUTLASS reference, word for word: passes on
  the CMP 50HX, RTX 3090, RTX 4090 and RTX 5070.
- Mock mining with zk-pow proof verification on all four cards.
- Live HeroMiners mining on all four cards: shares accepted, no rejects.

### Builds

- Windows and Linux packages are built with CUDA 12.9: native code for sm_75,
  sm_86 and sm_89, and PTX for sm_120 that the driver compiles on the first
  start. The driver's compiler gives faster RTX 50 code than CUDA 12.9 ptxas
  (RTX 5070: packed kernel 112.8 → 115.3, CUTLASS 99.5 → 106.6 TMAC/s).
- CUDA 13 was not used: its runtime requires driver 580 or newer.
- Windows packages are now built on a local build machine with the same steps
  as the CI workflow (build, smoke test, packaging, validation without
  toolchain paths); the CI workflow builds with CUDA 12.9 as well.
- Intel Arc (oneDNN / ESIMD), AMD/OpenCL and CPU paths are unchanged from
  v0.5-fork.5.
- Pool agent `cppminer/0.5-fork.6`.
