# CPPminer v0.5-fork.10 — TNet long poll

A small release for **TNet** (Requant test network): the miner hears of a new block as soon as the node
or pool has it. Pearl and Quantus are unchanged. **TNet has no miner fee**; **Quantus is still mined
without a developer fee**; the Pearl fee is unchanged (1%).

CPPminer is based on [1640675651/CPPminer](https://github.com/1640675651/CPPminer),
the Pearl/Quantus miner by @foolzhz. Development and release builds are maintained
in this fork; upstream submissions are made only when the fork owner chooses them.

## TNet

```sh
cppminer --algo tnet --rpc 193.187.93.29:19340 --payee <64-hex key hash> --worker rig1
```

- **Long poll.** A second network thread keeps `getwork payee longpollid` open; the Requant node (0.13.0
  or newer) and pool (0.14.0 or newer) answer it when the next block arrives, up to 60 s later. Mining
  restarts on the new tip at once instead of within the next once-a-second `getinfo`, and those 3600
  queries an hour per device stop. An older node or pool answers without `longpollid`: the miner keeps
  the once-a-second check and tries the long poll again every 10 s. The log says which:
  `tip watched by long poll` or `no long poll here: checking the tip every second`.
- Every request times out after 90 s, so a dropped connection is retried rather than waited on.
- A key hash comes from the Requant wallet: `requant-wallet create miner.wallet`, then
  `requant-wallet address miner.wallet`.

## Checked before release

- CMP 50HX (Linux): `--algo tnet --selftest`; 150 s solo against a Requant 0.13.0 node with
  `tip watched by long poll`, following four new blocks; 60 s in the Requant pool while it still ran
  0.13.0 (no long poll there): `no long poll here`, shares accepted, 3.6 M tickets/s as before.
- The Windows and Linux packages are built and checked as for v0.5-fork.9 (Windows VM, Ubuntu 24.04
  container).
- Pearl and Quantus code is the same as in v0.5-fork.9.
